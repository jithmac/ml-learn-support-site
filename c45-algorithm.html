Decision Trees: C4.5 Algorithm

Solving ID3's limitations: Gain Ratio penalty for many-valued attributes, continuous numerical thresholds, and tree pruning to stop overfitting.

Problems with ID3 & The C4.5 Solution

Why ID3 Struggles in Practice

Even though the ID3 algorithm was a big step forward for decision trees, it has three big problems in real life: it favors attributes with many values, it cannot easily handle continuous numbers, and it easily overfits. To fix these issues, Ross Quinlan created the improved C4.5 algorithm.

In our simple tennis example with 10 rows, ID3 works great. But with real-world data, ID3 runs into serious issues. Let's look at the three main problems with ID3, and how C4.5 fixes each one.

1

Information Gain Favors Many-Valued Attributes

The Many-Values Trap
Unfair Bias

ID3 picks the feature with the highest Information Gain. But this rule has a serious flaw: it unfairly favors features that have a lot of different values (like ID numbers), even when those features are useless for making predictions.

How Information Gain Works

The general idea behind Information Gain is:

Information Gain = Entropy Before Split − Entropy After Split

Now imagine a feature with lots of unique values, like Student_ID, Phone_Number, or Date. When you split on this feature, it breaks the data into many tiny groups—and each group has only 1 student (or very few).

The Fake High Gain

When a group has only 1 data point, there is no uncertainty at all. That means the entropy of every group drops straight to 0:

1 student per group → Entropy = 0
Entropy after split = 0
Information Gain = Entropy Before − 0 = Huge Fake Gain!

This is completely misleading. ID3 thinks Student_ID is the best feature in the whole dataset, simply because it split the data into tiny single-item groups.

Why this is a problem: Many smaller partitions create an artificially higher Information Gain. The tree simply memorizes every student by their ID. When a new student arrives with a new ID, the tree cannot classify them at all!
2

ID3 Cannot Practically Use Continuous Attributes

Working with Numbers
Impractical for Numbers

ID3 was only designed to work with fixed categories (like Outlook = {Sunny, Overcast, Rain}). In real life, most data consists of continuous numbers (like Temperature = 24.3°C, Age = 25, or Salary = $50,000).

Too Many Branches & Partitions

If you try to give continuous numbers to ID3 directly, it treats every single number as its own separate category:

1,000 different temperatures → 1,000 separate branches!
Each branch gets only 1 or 2 rows.

Entropy cannot practically be calculated this way. It creates too many branches, too many tiny partitions, and makes the Information Gain calculation completely impractical.

No Built-in Cutoff Points

To use numbers properly, an algorithm must find a sensible cutoff threshold (such as Temperature ≤ 25°C vs. Temperature > 25°C).

ID3 has no way to find cutoff points automatically. It cannot sort numbers or create binary splits, so it cannot handle continuous data on its own.

Why this is a problem: Real data is full of numbers. Because ID3 creates too many branches and cannot practically get entropy for continuous attributes, it cannot be used on numerical datasets without manual grouping beforehand.
3

Overfitting: Trees Become Too Specific

Fails on New Data
Generalization Failure

Overfitting happens when a decision tree becomes too specific to the training data. It memorizes everything—including noise, mistakes, and unusual exceptions—so it fails to make good predictions on new, unseen data.

Always Chasing Highest Gain

ID3 always searches for the highest Information Gain. It keeps splitting greedily until every single leaf is 100% pure (Entropy = 0) or it runs out of features.

Greedy splits on noise → Overly complex trees
Training accuracy = 100% (Pure Memorization!)

If one student in the training data was sick and unexpectedly failed the exam despite studying hard, ID3 creates extra branches just to isolate that single unusual row.

No Way to Prune (Trim) Branches

Because the tree is shaped around every little quirk and noise in the training set, it fails when you test it on new, unseen data.

ID3 has no pruning mechanism. It cannot stop early, and it cannot cut back branches that are too specific or only fit noise.

Why this is a problem: Overfitting creates trees that are too specific to the given dataset. By always chasing the highest Information Gain, ID3 includes noise in the tree, making it fail on general, unseen data.
✨ The Solution

The Solution: The C4.5 Algorithm

To fix all these problems with ID3, Ross Quinlan created the C4.5 algorithm in 1993. C4.5 keeps the good ideas of ID3, but fixes its three biggest weaknesses:

Ross Quinlan (1993)

1. Gain Ratio

Fixes Many-Valued Attributes

Instead of simple Information Gain, C4.5 uses Gain Ratio. It penalizes attributes that split data into too many tiny pieces (like Student_ID), so they don't get chosen unfairly.

Gain Ratio = Information Gain / Split Info
Penalizes attributes with too many tiny groups.

2. Handles Numbers

Fixes Continuous Attributes

C4.5 can handle numbers easily. It sorts the numbers from smallest to largest and tests smart cutoff points (for example, Age ≤ 30 vs Age > 30). This turns continuous numbers into a simple yes/no split.

Tests: Feature ≤ Cutoff Point
Finds the best cutoff point automatically.

3. Tree Pruning

Fixes Overfitting

C4.5 stops the tree from becoming too specific. After growing the full tree, it cuts off (prunes) branches that only fit noise or don't help with accuracy. This keeps the tree simpler so it works much better on new data.

Cuts off branches that fit noise
Keeps the tree simpler and more accurate on new data.

Simple Comparison: ID3 vs. C4.5

How C4.5 improves on the main problems of ID3:

Feature ID3 Algorithm (Older) C4.5 Algorithm (Improved)
Splitting Rule Information Gain
Favors features with many values. 		Gain Ratio
Penalizes features with too many values.
Many-Valued Features (like ID) ❌ Vulnerable: Picks IDs with fake high gain, making useless 1-row branches. ✔️ Protected: Penalizes IDs so they are not chosen unfairly.
Continuous Numbers (like Age, Price) ❌ Not supported: Creates too many branches; cannot handle numbers directly. ✔️ Fully supported: Automatically finds cutoff points (like Age ≤ 30).
Overfitting (Too Specific) ❌ No pruning: Grows too deep, memorizes noise, and fails on new data. ✔️ Pruning: Cuts off branches that only fit noise, keeping the tree simple.
Missing Values ❌ Fails: Cannot handle rows with missing data. ✔️ Handled: Can handle missing data safely.
Key Takeaway: ID3 proved that computers could build decision trees using entropy. But C4.5 made them practical for real-world use by handling numbers, stopping overfitting with pruning, and fixing the bias toward many-valued features.
📊 Step-by-Step Walkthrough

A Simple Example: How C4.5 Handles Continuous Numbers

Let's walk through a simple 6-row dataset with continuous temperature numbers. We will see exactly how C4.5 finds a cutoff threshold, calculates SplitInfo and Gain Ratio, avoids the ID trap, and builds a clean decision tree.

1

The Sample Dataset (6 Days)

Here is our small dataset. Notice that Temperature (°C) is a continuous number, Wind is categorical, and Day_ID is a unique identifier:

Day_ID Temperature (°C) Wind Play Tennis (Target)
D1 15 °C Weak ✖ No
D2 18 °C Strong ✖ No
D3 21 °C Weak ✔ Yes
D4 24 °C Strong ✖ No
D5 27 °C Weak ✔ Yes
D6 30 °C Weak ✔ Yes
Total Dataset: 6 Days → 3 Yes, 3 No.
Baseline Entropy: E(S) = −[ (3/6)log2(3/6) + (3/6)log2(3/6) ] = 1.0000 bit
2

How the Threshold (Cutoff Point) is Derived

How does C4.5 turn continuous numbers into a simple yes/no test? It derives a Threshold in three simple steps:

  1. Sort the numbers: Sort Temperature in ascending order.
  2. Find where the outcome changes: Look at adjacent rows where Play switches between No and Yes.
  3. Compute midpoint candidate thresholds: Take the average between adjacent values: Threshold = (Val₁ + Val₂) / 2.
Visualizing the Sorted Numbers & Candidate Cutoff Thresholds:

Among the candidate thresholds, Threshold = 19.5°C produces the cleanest division:
• Left (≤ 19.5°C): { D1 (15°C, No), D2 (18°C, No) } → 2 No, 0 Yes (100% Pure! Entropy = 0.0000)
• Right (> 19.5°C): { D3, D4, D5, D6 } → 3 Yes, 1 No (Entropy = 0.8113)
• Information Gain: Gain = 1.0000 − [ (2/6)(0) + (4/6)(0.8113) ] = 0.4591 bits
3

What is SplitInfo and Gain Ratio?

💬 The Fundamental Difference in Question:
ID3 asks:
“Which split gives me the most information?”
C4.5 asks:
“Which split gives me a good amount of information relative to how much splitting it creates?”
What is SplitInfo?

SplitInfo measures how fragmented the split is. It ignores the target classes and only looks at how many branches the data is chopped into.

SplitInfo = − ∑ ( |Sᵢ| / |S| ) log₂( |Sᵢ| / |S| )

• 2 balanced groups: SplitInfo is small (~1.0 bit).
• Many tiny groups (like IDs): SplitInfo is huge! It acts as a penalty for over-splitting.

What is Gain Ratio?

Gain Ratio is simply Information Gain divided by SplitInfo:

Gain Ratio = Information Gain / SplitInfo

This balances the score: if a feature gets a high Information Gain just by splitting data into dozens of tiny pieces, its huge SplitInfo divides and lowers its score!

💡 The "Aha!" Insight: Same Exact Equation, Different Lens!

Notice something remarkable? SplitInfo uses the exact same mathematical entropy formula as Information Gain: −∑ pᵢ log₂(pᵢ). The difference is purely what it measures:

1. Information Gain = Target Entropy
Measures spread of the Target Variable

Calculates the entropy of different target classes (e.g. Yes vs. No) inside each group:

pᵢ = Proportion of Target Classes
p₁ = P(Play = Yes),   p₂ = P(Play = No)
“How mixed or pure are the answers we want to predict?”
2. SplitInfo = Branch Entropy
Measures spread of the Attribute Branches

Completely ignores the target classes! Instead, calculates the entropy of each branch on the same attribute:

pᵢ = Proportion of data in Branch i
p₁ = |Branch₁| / |S|,   p₂ = |Branch₂| / |S|
“How scattered or fragmented are the branches of this split?”
🎯 Why this is brilliant: If an attribute splits data into 6 tiny single-item branches (like Day_ID), the branches are maximally fragmented. Its branch entropy is at the maximum possible value (log₂(6) = 2.585 bits), creating a heavy penalty that protects against bad splits!
Calculation for Temperature ≤ 19.5°C:
• Branch 1 (≤ 19.5°C): has 2 rows → p₁ = 2/6 = 1/3
• Branch 2 (> 19.5°C): has 4 rows → p₂ = 4/6 = 2/3
• SplitInfo (Branch Entropy) = −[ (1/3)log₂(1/3) + (2/3)log₂(2/3) ] = 0.9183 bits
• Gain Ratio = Information Gain / SplitInfo = 0.4591 / 0.9183 = 0.5000
4

How Gain Ratio Fixes the Problem with Information Gain

Now look at what happens when we compare Day_ID against Temperature ≤ 19.5°C. This is where the magic of Gain Ratio reveals itself:

Under ID3 (Information Gain Alone) ID3 gets tricked!

Day_ID splits our 6 rows into 6 individual groups of 1 row each. Every single group has Entropy = 0:

• Gain(Day_ID) = 1.0000 − 0 = 1.0000 bit
• Gain(Temp ≤ 19.5) = 0.4591 bits
Result: ID3 picks Day_ID because 1.0000 > 0.4591. The tree is completely useless on new days!
Under C4.5 (Gain Ratio with Penalty) C4.5 Fixes It!

C4.5 calculates SplitInfo for Day_ID. Because it splits into 6 pieces, its penalty is huge:

• SplitInfo(Day_ID) = log₂(6) = 2.5850 bits
• Gain Ratio(Day_ID) = 1.0000 / 2.5850 = 0.3868
• Gain Ratio(Temp ≤ 19.5) = 0.4591 / 0.9183 = 0.5000
Result: 0.5000 > 0.3868 → C4.5 picks Temperature ≤ 19.5°C!
Key Insight: Gain Ratio completely eliminates the multi-valued attribute trap. The high SplitInfo penalty ensures that meaningless identifiers (like Day_ID or Student_ID) cannot win simply by creating tiny single-item groups.
5

The Final Trained Decision Tree

After choosing Temperature ≤ 19.5°C as the root split:

  • Left Branch (≤ 19.5°C): 100% pure (D1, D2 → 2 No, 0 Yes). Stops immediately as a leaf node: Play = NO.
  • Right Branch (> 19.5°C): 4 rows (D3, D4, D5, D6). C4.5 evaluates the remaining feature Wind:
    • Wind = Weak (D3, D5, D6) → 3 Yes, 0 No → Play = YES (100% pure leaf)
    • Wind = Strong (D4) → 0 Yes, 1 No → Play = NO (100% pure leaf)
Learned C4.5 Rules:
1. IF (Temperature ≤ 19.5°C) → Play = NO (Days: D1, D2)
2. IF (Temperature > 19.5°C) AND (Wind == Weak) → Play = YES (Days: D3, D5, D6)
3. IF (Temperature > 19.5°C) AND (Wind == Strong) → Play = NO (Day: D4)
