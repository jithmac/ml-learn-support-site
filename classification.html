Classification & Decision Trees

Supervised learning method 01: Discovering patterns to assign observations into distinct categories, and how decision trees recursively partition data from root to leaves.

Supervised Learning Method 01: Classification

Method Definition

Classification is used to predict categorical output.
It basically categorizes input data into groups — normally two groups (Binary Classification).

In classification, the output is not a continuous measurement like distance or temperature. Instead, it is a discrete tag or group membership.

1. Binary Classification (Normally Two Groups)

The most widespread scenario in machine learning: dividing observations into one of two mutually exclusive categories.

  • Student Outcome: Pass vs. Fail (as in our Student example)
  • Email Filtering: Spam vs. Not Spam (Ham)
  • Financial Fraud: Legitimate vs. Fraudulent Transaction
  • Medical Diagnosis: Positive (Disease present) vs. Negative (Healthy)
  • Customer Retention: Churn (Cancels subscription) vs. Retained

2. Multi-Class Classification (More than Two Groups)

When the classification problem expands beyond two choices, the model learns to assign inputs into one of three or more possible groups:

  • Academic Grades: Grade A, Grade B, Grade C, Grade D, or Grade F
  • Handwritten Digit Recognition: Digits 0, 1, 2, 3, 4, 5, 6, 7, 8, or 9 (the classic MNIST problem)
  • Sentiment Analysis: Positive, Neutral, or Negative

Decision Tree Algorithms

What is a Decision Tree?

A decision tree is a flowchart-like structure that makes decision rules by asking a sequence of questions about the dataset.

Under Supervised Learning, decision trees are among the most intuitive and widely used algorithms. They mimic human reasoning: rather than evaluating complicated equations all at once, a decision tree breaks a problem down into a sequence of simple, interpretable questions about the features until reaching a confident prediction.

In practice, three landmark algorithms defined the development of decision trees — ID3, C4.5, and CART:

Ross Quinlan (1986)

ID3 Iterative Dichotomiser 3

The pioneer algorithm that introduced decision tree induction to modern machine learning.

Splitting Metric Entropy & Information Gain
Split Type Multi-way categorical splits
Target Task Classification only

Selects the feature that yields the greatest Information Gain. Designed strictly for discrete/nominal features; cannot natively handle continuous numeric ranges or missing values.

Explore ID3 Walkthrough ↓
Ross Quinlan (1993)

C4.5 Successor to ID3

A major breakthrough addressing ID3's limitations with continuous variables and feature bias.

Splitting Metric Gain Ratio (Normalized Gain)
Split Type Multi-way & Continuous Thresholds
Target Task Classification only

Uses Gain Ratio to eliminate ID3's bias toward attributes with many distinct values. Supports continuous features (e.g., Temperature > 25°C), handles missing data, and performs post-pruning.

Explore C4.5 Walkthrough ↓
Breiman et al. (1984)

CART Classification & Regression Trees

The industry standard widely implemented in modern tools like Scikit-Learn.

Splitting Metric Gini Impurity (or MSE / Variance)
Split Type Strictly Binary (2 branches)
Target Task Classification & Regression

Constructs strictly binary trees (each split generates exactly two outcomes). Versatile enough to handle both discrete classes (via Gini Impurity) and continuous numerical targets (via MSE).

The 4 Key Components Explained Simply

Every decision tree — from this simple weather example to deep models with hundreds of branches — is assembled from four fundamental parts:

Starting Point

1. Root Node

What it is: The first node of the tree. Uses the best attribute to separate data into sets. Acquired by splitting metrics like Gini Impurity, Gain Ratio, or Entropy.

In our example:

“Is it raining?” is the root node. Everything starts here: before checking any other factor, we first examine whether rain is falling.

Decision Pathways

2. Branches

What they are: Connects nodes together. Represents the outcome or decision resulting from the test performed on an attribute.

In our example:

The lines labeled “Yes” and “No”. Answering “No” to rain directs you immediately to Play, while answering “Yes” routes you to the next question.

Intermediate Tests

3. Internal Nodes (Decision Nodes)

What they are: The nodes that come after the root node. Represents the test performed on the selected attribute.

In our example:

“Is it windy?” is an internal node. It is evaluated conditionally only if the answer to the root node was “Yes” (it is raining).

Final Predictions

4. Leaf Nodes (Terminal Nodes)

What they are: The endpoints of the tree with no outgoing branches. They hold the model's final prediction, decision, or class label.

In our example:

“Play” and “Don't Play” are the leaf nodes. Once an observation lands on a leaf node, all questioning stops and the final decision is rendered.

Hunt's Algorithm

The Base of ID3, C4.5, and CART

Hunt's Algorithm is a basic, recursive method for building a decision tree.
It is the foundational core behind modern decision tree algorithms (such as ID3, C4.5, and CART), defining the fundamental recursive splitting loop that grows a tree from top to bottom.

Hunt's algorithm builds a decision tree by dividing a dataset using a 5-step recursive cycle. Below is a simple 4-student reference dataset, followed by a step-by-step roadmap showing how Hunt's algorithm evaluates features, partitions the data, and seals every branch into pure leaf nodes.

Reference Mock Dataset

Student Exam Performance Dataset

We use this clean 4-student reference dataset across all 5 steps below to trace exactly how Hunt's algorithm works. Our target is to predict whether a student will Pass or Fail based on their Attendance and Study Hours.

01
Step 01 of 05 Attribute Selection

Selecting the Best Attribute

The algorithm begins at the top by selecting the single best attribute to split the dataset. In advanced decision tree algorithms (ID3, C4.5, CART), this choice is mathematically scored using metrics like Information Gain or Gini Impurity.

Referring to our Dataset:

We evaluate our two candidate features against the 4 students:
• Attendance: High Attendance isolates Student 1 & Student 2, both of whom passed (100% pure Pass!). Low Attendance leaves Student 3 (Pass) and Student 4 (Fail).
• Study Hours: High Study Hours isolates Student 1 & Student 3 (Pass), while Low Study Hours leaves Student 2 (Pass) and Student 4 (Fail).
Because splitting on Attendance immediately yields a perfectly pure branch of 2 passing students, Attendance is selected as the Root Node attribute!

✓ Selected: Attendance creates the cleanest separation on our 4-student dataset.
02
Step 02 of 05 Data Partitioning

Splitting the Data Using the Root Node

Once the root attribute is chosen, the algorithm creates outgoing branches for each attribute value and channels the dataset records into their corresponding child branches.

Referring to our Dataset:

The 4 students are routed along the branches of the Attendance root node:
• Left Branch (Attendance = High): Receives Student 1 (Pass) and Student 2 (Pass).
• Right Branch (Attendance = Low): Receives Student 3 (Pass) and Student 4 (Fail).
The original dataset of 4 students is now partitioned into two smaller subsets of 2 students each.

03
Step 03 of 05 Purity Verification

Examine the Left Child

The algorithm inspects the records in the left branch. If all records belong to the exact same class (pure), further questioning is unnecessary — the node is immediately converted into a permanent Leaf Node. If classes are mixed, it must be split again.

Referring to our Dataset:

Examining the left branch:
• Contains Student 1 (Pass) and Student 2 (Pass).
• Every single record in this branch shares the identical outcome: Pass.
• Because this subset is 100% pure (no Fail records exist here), Hunt's algorithm converts this node directly into a Leaf Node labeled "Pass".
Splitting is finished along this branch!

04
Step 04 of 05 Impurity Detection

Examine the Right Child

The algorithm applies the exact same purity check to the right child subset. If pure, it becomes a leaf node. If records are mixed across multiple classes, it cannot become a leaf node yet and must be marked for another split.

Referring to our Dataset:

Examining the right branch:
• Contains Student 3 (Pass) and Student 4 (Fail).
• The outcomes are mixed: 1 Pass vs. 1 Fail.
• Because this subset is impure, we cannot assign a single final leaf label yet.
Hunt's algorithm flags this node as an Internal Node that must undergo another split using our remaining feature (Study Hours).

Right Child Evaluation

IMPURE (MIXED)
⚠ Cannot Convert to Leaf

Mixed: 1 Pass, 1 Fail

Contains: Student 3 (Pass) • Student 4 (Fail)

⚠ Action Needed: One question was not enough. This branch must split again using the next attribute!
05
Step 05 of 05 Recursive Completion

Continue Recursively Until All Branches End in Leaf Nodes

Hunt's algorithm recursively repeats Steps 1 to 4 on any remaining mixed child nodes. It selects the next best attribute to split each impure branch until every path in the tree reaches a pure leaf node.

Referring to our Dataset:

For the impure right branch (Students 3 & 4), the algorithm splits on our remaining attribute: Study Hours:
• Study Hours = High: Isolates Student 3 (Pass) → Sealed as Leaf Node: Pass.
• Study Hours = Low: Isolates Student 4 (Fail) → Sealed as Leaf Node: Fail.
All 4 students have now reached a pure leaf node with 100% confidence. The recursive cycle terminates — our decision tree is complete!
