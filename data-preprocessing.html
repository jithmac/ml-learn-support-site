Data Preprocessing

A machine learning model is as good as the data it is learning from. Before using data, they must be properly prepared for the model training.

If your training data is distorted, incomplete, or chaotic, even the most sophisticated deep neural network will learn wrong conclusions. That is why professional data scientists routinely spend 70% to 80% of their project time preparing and refining datasets before running an algorithm.

What is data?

Core Definition

Data is simply raw facts that have not yet been processed into meaningful information.

Think of data as unorganized measurements, numbers, characters, symbols, or observations collected from the world without intrinsic context. On its own, a raw number like 72000 or a word like "France" conveys no conclusion. It only becomes information when it is organized, structured, and given context.

Unprocessed observations with no built-in meaning or context.

Step 2: Processing

Preprocessing & Context

Step 3: Outcome

Information

Interpreted facts ready for decision making and mathematical modeling.

"A 44-year-old French professional earning $72k."

2. Statistical Classification (Quantitative vs Qualitative)

When examining variables inside a dataset, statistics divides them into two major branches based on whether they measure mathematical amounts or descriptive qualities:

Statistical Data Taxonomy

Data variables fall into numbers you calculate with (Quantitative) or labels you categorize with (Qualitative).

1. Quantitative Data

Numerical • Measurable

Variables expressed as real numbers where arithmetic calculations (averages, sums, differences, and scalings) have genuine mathematical meaning.

1.1 Countable Integers Only
Discrete Data

Values that can only take distinct, separate, countable numbers. They cannot be divided into fractional parts.

Quick Test: Can you have 2.5 of it? If NO, it is Discrete.
Real-World Examples:
Number of cars Website clicks Hospital beds Rooms in a house
Interactive Test
3 items

Notice: Discrete values jump in whole numbers (1, 2, 3, 4). You cannot have 3.4 items.

1.2 Measurable Infinite Decimals
Continuous Data

Measurements that can take any value along an unbroken, continuous scale with infinite possible decimal subdivisions.

Quick Test: Can you measure it with decimals? If YES, it is Continuous.
Real-World Examples:
Salary ($63,777.78) Age (38.78 yrs) Temperature (24.6°C) Height & Weight
Interactive Test
$63,777.78

Notice: Continuous values flow smoothly with infinite decimal points ($63,777.78).

2. Qualitative Data

Categorical • Descriptive

Variables expressed as descriptive labels, characteristics, or categories rather than raw numerical measurements.

2.1 Unordered No Hierarchy
Nominal Data

Categories or names that have no natural order or ranking. One label is mathematically neither greater nor smaller than another.

Quick Test: Does one category outrank another? If NO, it is Nominal.
Real-World Examples:
Country (France, Spain, Germany) Blood Type Color Gender

2.2 Ordered Ranked Hierarchy
Ordinal Data

Categories that possess a clear, meaningful order or rank, though the mathematical distance between ranks cannot be measured.

Quick Test: Is there a natural hierarchy? If YES, it is Ordinal.
Real-World Examples:
Satisfaction (Low, Med, High) Education (BSc, MSc, PhD) Sizes (S, M, L, XL)

Why Real-World Data is Not Ready for Machine Learning

Here is the harsh reality that every practitioner must confront: None of these real-world data types are directly suitable for machine learning algorithms out of the box.

Real-world data collected from human forms, IoT sensors, web scrapers, and business databases is messy, imperfect, and mathematically incompatible with learning algorithms:

1. Incomplete

Missing values and NaN entries occur constantly when users skip optional form fields or sensors drop packets. Standard matrix math fails instantly when encountering null values.

2. Noisy & Corrupted

Contains measurement errors, typos, and extreme outliers (e.g. an Age of 350 or a negative salary). Outliers skew gradient descent and pull regression lines away from the true pattern.

3. Inconsistent

Conflicting formats, duplicate records, or mismatched naming conventions (e.g., "Spain" vs "spain" vs "ES", or dates stored in mixed conventions).

4. Not in a Usable Format

Machine learning models are strictly mathematical systems calculating vector dot products and matrix multiplications. They cannot compute equations directly on text strings like "France" or "Yes".

What Data Preprocessing Does

Data preprocessing is the vital bridge: it cleans the noise, imputes missing values, translates categorical text into numeric vectors, scales numerical ranges, and splits the data into training and evaluation sets. It transforms raw chaos into clean, structured numerical tensors that learning algorithms can compute smoothly without error.

Important Facts About Preprocessing Tasks

Data preprocessing is not just a mechanical checklist of coding steps; it is governed by foundational mathematical and statistical principles. Below are the three critical pillars that every machine learning practitioner must master: Dataset Splitting, Feature Scaling, and Categorical Encoding.

1

Split Dataset

Separating training knowledge from evaluation truth
Train / Test Division

This step splits the dataset into distinct subsets using percentages. In machine learning, an algorithm must never be evaluated on the same data it learned from. Common standard split ratios in practice are:

80% Training
20% Testing
✓ 8 of 10 samples for learning patterns 🔒 2 of 10 samples held out for testing

Training Set (Larger Portion: 70% – 80%)

The larger portion is always the training set. The machine learning model uses this data to discover underlying patterns, optimize mathematical weights, and adjust its decision boundaries.

x_train, y_train • 80% of rows

Testing Set (Smaller Portion: 20% – 30%)

The smaller portion is the testing set. It remains completely hidden and untouched during model training. It serves as an unbiased benchmark to test whether the model can generalize to unseen real-world data.

x_test, y_test • 20% unseen rows
Why is the larger portion always the training set?

Algorithms need substantial volumes of data to detect nuanced statistical patterns without being misled by random noise. A 20% to 30% holdout provides more than enough statistical power to test real-world accuracy without starving the model of learning material.

⚡ Pipeline Rule: Always split before feature scaling to prevent Data Leakage (test statistics contaminating the training process).
2

Feature Scaling

Balancing numeric magnitudes across variables
Magnitude Balancing

Feature scaling is very important when training machine learning models to get a proper, reliable output. What feature scaling does is bring numerical features onto a similar, comparable mathematical range.

This is done to make sure that one feature does not have an unintended, disproportionately large influence on a machine learning model just because it happens to be measured in bigger numbers.

📌
Core Definition: A feature is an individual variable or a column in the dataset that normally contains one specific type of data (for example: Country, Age, or Salary).

💡 Simple Example: Why Scale Differences Create Unfair Bias

Suppose a model predicts customer behavior using two features: Age and Salary. Look at their raw numbers:

Feature 1: Age
Values range from 27 to 50
Max difference: 23 years
Feature 2: Salary
Values range from $48,000 to $83,000
Max difference: $35,000 dollars

In real life, a 10-year age difference represents a major generational gap, while a $1,000 salary difference is minor. However, when computing distances:
• Age squared difference: (50 - 27)² = 529
• Salary squared difference: (83,000 - 48,000)² = 1,225,000,000
Because 1,225,000,000 is over 2.3 million times larger than 529, the model will essentially ignore Age and make all its decisions based solely on Salary, simply because Salary is measured in thousands of dollars! Feature scaling eliminates this unfair distortion.

Why Feature Scaling Matters: Distance & Size-Dependent Algorithms

Many machine learning algorithms rely directly on geometric distance calculations between data points or gradient magnitudes. Without scaling, larger features overpower these algorithms completely:

K-Nearest Neighbors (KNN): Calculates Euclidean distance to classify neighbors
K-Means Clustering: Partitions data clusters around spatial centroids
Gradient Descent (Neural Nets & Regressions): Unscaled inputs cause erratic oscillation
Support Vector Machines (SVM): Hyperplane margins depend directly on distances

Manual Feature Scaling Methods & Their Mathematical Equations

1. Standardization
Z-score Normalization

Centers the distribution around mean μ = 0 with standard deviation σ = 1. Preserves outlier information and is ideal for normally distributed data.

z =
x − μ σ
x — original feature value
μ — mean of the feature
σ — standard deviation
z — standardized value
In Scikit-Learn: StandardScaler()
2. Normalization
Min-Max Scaling

Shifts and rescales values into a fixed bounded range between 0.0 and 1.0. Ideal when you know distribution boundaries, though sensitive to extreme outliers.

xnorm =
x − xmin xmax − xmin
x — original feature value
xmin — minimum column value
xmax — maximum column value
xnorm — normalized value [0, 1]
In Scikit-Learn: MinMaxScaler()
3

Encoding Categorical Data

Translating text categories into mathematical numbers
Text to Numbers

Machine learning algorithms compute mathematical equations (vector dot products like W · x + b) and cannot compute on raw text strings like "France" or "Yes".

There are two primary methods of categorical encoding: One-Hot Encoding and Label Encoding. Knowing which one to use depends strictly on whether the categories have a natural ranking or order.

One-Hot Encoding

Nominal (Unordered)

When to use: Use One-Hot Encoding when there is no particular order or ranking among the categories.

Why: If you encoded countries as 0, 1, 2, the algorithm would incorrectly assume that Germany (2) is mathematically "greater than" France (0). One-Hot encoding avoids this false bias by creating separate binary (0 or 1) indicator columns for each category.

Raw CountryFranceGermanySpain
France100
Spain001
Germany010
💡 Other Examples: Colors (Red, Blue, Green), Blood Types (A, B, AB, O), Cities, Browser Types.

Label Encoding

Ordinal (Ordered)

When to use: Use Label Encoding when there is a clear, meaningful order or hierarchy among the categories, or for the dependent target variable (y).

Why: Sequential integers (0, 1, 2, ...) preserve the natural progression and hierarchy of ranks without expanding your dataset into excessive dummy columns.

Rank CategoryHierarchyEncoded Integer
LowLowest Tier0
MediumIntermediate Tier1
HighHighest Tier2
💡 Other Examples: Education (High School → 0, BSc → 1, MSc → 2, PhD → 3), Sizes (S → 0, M → 1, L → 2), Target Purchased (No → 0, Yes → 1).
